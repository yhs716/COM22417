실습 순서 · 정제 변경 / 데이터 추가 / 모델 정리
  1. 정제 전후 비교: 학습데이터에서 RAW 전처리 저장 → RAW 최초 생성·TEST 평가 → CLEAN 전처리 저장 → CLEAN 최초 생성·같은 TEST 평가. 두 방식은 준비값과 모델을 따로 보관합니다.
  2. 정제 규칙 수정: 프로시저의 CLEAN 전처리 INSERT SELECT를 수정하고 F5로 DB에 적용 → CLEAN 전처리 실행·저장 → 저장값 확인 → CLEAN 전체 다시 학습 → TEST·예측 비교.
  3. 학습 제공 행 수정: PREPARED의 해당 방식·TRAIN 행에서 FIT_YN과 EXCLUDE_REASON을 직접 수정 → COMMIT → 전체 다시 학습. 모델은 저장된 학습 제공 행만 SELECT합니다. PREPARE를 다시 실행하면 수동 수정값도 원본 기준으로 교체됩니다.
  4. 학습 데이터 증가: 원본에 새로운 CASE_ID의 Y/TRAIN 행을 INSERT → VALIDATE → COMMIT → 해당 방식 전처리 저장 → 전체 다시 학습. 2배·3배 증가도 저장된 전체 TRAIN을 재학습하며 기존 트리를 증분 갱신하지 않습니다.
  5. 모델 정리: 선택 모델 삭제는 DBMS_DATA_MINING.DROP_MODEL을 호출합니다. 다른 모델·테이블·데이터는 유지합니다. DM$ 내부 객체를 직접 삭제하지 마세요.

숫자 변환과 범위 검사는 PREPARED에 저장합니다. RAW/CLEAN 모두 변환 실패·빈 값은 NULL이며 CLEAN은 범위 밖 숫자도 NULL로 저장합니다. 학습 SELECT는 선택 방식·TRAIN·FIT_YN=Y만 읽습니다.

TEST·정답·예측 입력은 고정하고 모델만 바꿔 비교하세요. 정제나 학습 행 증가가 성능 향상을 보장하지 않습니다. 데이터 수정은 SQL Developer에서 직접 실행·COMMIT합니다.
