학습·TEST·예측의 컬럼 연결과 SQL 작성 방법

모델은 설명변수의 이름으로 값을 연결합니다. 새 사례의 값은 달라도 되며, 의미·단위·타입·전처리 규칙은 학습할 때와 맞춥니다.

컬럼 순서는 달라도 됩니다. USING *는 입력행에서 모델에 필요한 설명변수를 이름으로 찾습니다. 이 모델에서 고유키로 지정한 CASE_ID, 타깃으로 지정한 SIGNAL, 학습에 쓰지 않은 관리 컬럼이 함께 있어도 설명변수로 사용하지 않습니다.

기준은 PREPARED에 저장된 설명변수의 이름과 타입입니다. DATA·PREDICT 원본은 오류를 보존하려고 숫자도 VARCHAR2로 보관합니다. 전처리 INSERT SELECT가 숫자 4개를 NUMBER로 변환해 PREPARED에 저장하고, 학습·TEST·예측 SELECT는 그 저장값을 읽습니다. 원본의 unknown을 그대로 모델에 전달하면 숫자 변환 오류가 날 수 있습니다.

기본과제의 컬럼별 역할
컬럼명 · 한글 명칭학습·TEST예측 데이터와 연결 기준
RETURN_PCT
이번 주 등락률		설명변수 · NUMBER같은 이름·계산식. 값에는 %를 넣지 않고 1.2처럼 숫자만 전달합니다.
RANGE_PCT
이번 주 고저폭		설명변수 · NUMBER같은 이름·계산식·단위를 사용합니다.
VOLUME_CHANGE_PCT
거래량 증감률		설명변수 · NUMBER같은 이름·계산식·단위를 사용합니다.
CLOSE_PRICE
이번 주 종가		설명변수 · NUMBER같은 이름·가격 단위를 사용합니다. $·USD를 값에 붙이지 않습니다.
STOCK
종목 코드		설명변수로 제공 · VARCHAR2학습과 같이 공백을 제거하고 대문자로 바꿉니다. 모델이 실제로 사용하는 속성은 모델 등록 결과에서 확인합니다.
CASE_ID
사례번호		고유키 · NUMBER학습 행의 번호와 같을 필요가 없습니다. 이 웹에서는 예측 행을 구분하고 결과를 연결하므로 중복 없는 번호가 필요합니다.
SIGNAL
다음 주 신호		TRAIN의 학습 정답
TEST의 비교 정답		예측 CSV의 선택 컬럼입니다. 정답을 모르면 비우거나 CSV에서 생략합니다. 테이블에는 컬럼을 유지하며, 값이 있어도 이 모델의 설명변수로 사용하지 않습니다.
WEEK_ENDING
기준일		기간 검증·표시예측 날짜를 표시합니다. 설명변수에 포함하지 않습니다.
SPLIT
학습·평가 구분		TRAIN/TEST 행 선택예측 테이블에는 필요하지 않습니다.
USE_YN
사용여부		Y 사용 / N 제외예측 테이블에는 필요하지 않습니다.
PREP_MODE · SOURCE_KIND준비값의 방식·구분RAW/CLEAN과 TRAIN/TEST/PREDICT를 구분합니다. 모델 설명변수에서 제외합니다.
FIT_YN · EXCLUDE_REASON학습 제공 여부·제외 사유TRAIN의 FIT_YN=Y만 학습합니다. TEST는 비교 대상을 유지하고 PREDICT는 예측만 수행합니다.
UPDATED_AT
변경 시각		관리용 시각테이블의 관리 컬럼이며 설명변수에 포함하지 않습니다.
컬럼 추가·누락·이름 변경·타입 변경 시 동작
  • 이름 변경: 다른컬럼 AS CLOSE_PRICE처럼 학습 때의 이름으로 연결할 수 있습니다. 오타가 있으면 원래 설명변수가 누락된 상태로 처리될 수 있습니다.
  • 누락: Oracle은 남은 설명변수로 예측을 시도합니다. 성공해도 정상 입력이나 정확도를 보장하지 않으므로 필요한 설명변수를 모두 전달하세요.
  • 추가: 기존 모델이 사용하지 않는 컬럼은 무시합니다. 새 컬럼을 설명변수로 사용하려면 학습 SELECT에 추가하고 모델을 다시 만드세요.
  • 타입 변경: 숫자 문자열은 NUMBER로 변환될 수 있지만 unknown은 변환할 수 없습니다. DATE·RAW 등 변환할 수 없는 타입도 오류가 납니다. 같은 이름만 맞추어서는 충분하지 않습니다.
  • 전처리 저장: RAW는 숫자 변환 실패·빈 값만 NULL, CLEAN은 범위 밖 숫자도 NULL로 PREPARED에 저장합니다. 선택 모델의 같은 규칙을 TRAIN·TEST·예측의 INSERT SELECT에 적용합니다. 예측 실행은 해당 방식의 PREDICT 준비값을 교체하며 TRAIN·TEST를 변경하지 않습니다.
  • 웹의 고정 구조: PREDICTION 함수 자체는 고유키·타깃 없이도 호출할 수 있습니다. 이 웹은 행 연결과 CSV 적재를 위해 정의된 테이블 컬럼을 사용하므로, 테이블 컬럼을 삭제하려면 적재·조회 SQL도 함께 수정해야 합니다.

VS Code에서 Ctrl+P → sql/classifier.sql을 열고 PREPARE의 INSERT SELECT와 SQL-TRAIN·SQL-EVALUATE·SQL-PREDICT를 확인하세요. 모델 입력 컬럼은 sql/prepared_table.sql, 원본은 sql/schema.sql·sql/prediction_table.sql에서 수정합니다. 각 기능의 ?에 실제 코드와 수정 위치가 있습니다.

USING d.*를 한 행으로 이해하는 SQL 예제

아래 숫자는 문법 설명용 입력입니다. 이미 생성된 CLEAN 모델에 한 행을 조회하는 읽기 전용 예제이며, 원본 데이터·모델을 변경하지 않습니다. SIGNAL에 BUY를 넣어도 이 값을 정답으로 강제하지 않습니다. 웹 실행은 PREDICT 원본을 전처리해 PREPARED에 저장하고 해당 PREDICT 행을 읽습니다.

SELECT d.CASE_ID
     , PREDICTION(OML_BASIC_CLEAN_MODEL USING d.*) PREDICTED
  FROM
     (
      SELECT 1 CASE_ID
           , 1.2 RETURN_PCT
           , 2.5 RANGE_PCT
           , 5 VOLUME_CHANGE_PCT
           , 100 CLOSE_PRICE
           , 'AA' STOCK
           , 'BUY' SIGNAL
        FROM DUAL
     ) d
;
실제 Oracle에서 확인한 결과와 검증 범위

2026-11-17의 CLEAN 모델과 별도 예측 30행으로 20가지 입력 구성을 읽기 전용 검증했습니다. 원본 행·모델·프로시저는 보존했습니다. 아래는 그 모델에서 관찰한 결과이며, 이후 모델이나 데이터의 정확도를 보장하지 않습니다.
