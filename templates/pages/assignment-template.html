프로시저 호출 규약과 수정 반영

프로시저(p_action IN VARCHAR2, p_mode IN VARCHAR2, p_result OUT SYS_REFCURSOR, p_sql OUT CLOB)

고정 입력: p_action은 PREPARE / INIT / RETRAIN / ADD_TRAIN / DELETE / EVALUATE / PREDICT / VALIDATE, p_mode는 RAW / CLEAN입니다. 최초 학습은 모델 하나만 생성합니다.

테이블은 CASE_ID(고유키)를 유지하고 나머지 특성·정답 컬럼을 자유롭게 정합니다. 원본의 SPLIT·USE_YN과 준비 테이블의 PREP_MODE·SOURCE_KIND·FIT_YN·EXCLUDE_REASON을 유지하고, PREPARE에서 실제 학습 제공 조건을 구현합니다. CSV 헤더는 실제 컬럼명과 일치시킵니다.

고정 출력: EVALUATE는 VARIANT·ACTUAL·PREDICTED·N(건수), PREDICT는 CASE_ID·PREDICTED·PROBABILITY(0~1). 분류 라벨은 자유이며 Python에서 BUY/SELL로 제한하지 않습니다. 추가 출력 컬럼도 표에 표시합니다. p_sql은 실행한 SELECT 원문입니다.

객체·컴파일 상태·인자 규약만 확인합니다. 테이블이나 모델을 자동 생성하지 않습니다. SQL만 수정했다면 서버 재시작은 필요 없습니다.

SQL Developer 실행 순서
같은 DB 계정의 새 워크시트에 위 선택 테이블 SQL 전체를 붙여넣고, 글자 선택을 해제한 뒤 F5(스크립트 실행)를 누르세요. 출력에서 PL/SQL 블록과 CREATE TABLE의 성공 여부를 순서대로 확인합니다.
Ctrl+Enter는 커서 위치의 한 문장만 실행합니다. 마지막 COMMENT ON COLUMN만 실행했고 테이블이 없으면 ORA-00942가 납니다. CREATE가 실패했다면 이후 COMMENT 오류보다 앞선 첫 오류를 먼저 확인하세요.
1. 원본 DATA → 2. 전처리 PREPARED → 3. 예측 PREDICT → 4. 실행 프로시저 RUN 순서로 탭별 SQL을 실행합니다. 각 SQL의 첫 PL/SQL 블록이 해당 테이블만 확인·삭제한 뒤 CREATE합니다. 기존 행은 삭제되며 ROLLBACK할 수 없습니다. 미션 변경 후에는 프로시저도 새 컬럼에 맞춰 다시 적용하고 CSV 적재·전처리·재학습을 진행하세요.

    
RUN 프로시저 등록
테이블 3개를 먼저 생성하고 위 전체 SQL을 02_procedure.sql로 저장하세요. 같은 발급 계정에서 F5로 실행한 뒤 웹을 새로고침하면 객체 준비가 자동 확인됩니다. 기존 RUN 정의는 새 정의로 교체됩니다.

    
CHECK (SPLIT IN ('TRAIN', 'TEST'))는?
SPLIT에 TRAIN(학습) 또는 TEST(평가)만 허용하는 입력 검사입니다. 다른 값은 INSERT·UPDATE 시 오류가 나며, 데이터를 자동으로 나누거나 학습을 실행하지 않습니다.
CHECK만으로는 NULL을 막지 못합니다. 반드시 값을 입력하게 하려면 NOT NULL도 지정합니다. 생성 참고안은 원본 SPLIT에 두 규칙을 함께 사용합니다.
USE_YN의 Y/N, PREP_MODE의 RAW/CLEAN도 같은 방식으로 허용값을 제한합니다.
