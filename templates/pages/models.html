모델 개요·속성·설정·상세 뷰·변환·객체 상태의 SQL 보기

USER_는 본인 소유, ALL_는 접근 가능한 객체, DBA_는 DB 전체 정보이며 별도 권한이 필요합니다. VALID는 DB 객체 유효 상태입니다. 웹의 최신 학습 검증·선택 확정과는 다르며 TEST 정확도는 같은 TEST로 따로 평가합니다.

모델 생성 후 ‘모델 정보 조회’를 누르세요. 생성 전에도 ?에서 조회 SQL과 읽는 방법을 확인할 수 있습니다.

어떤 뷰를 공부하나요? · 결과 읽는 방법
USER_MINING_MODELS
모델명·분류 목적·알고리즘·생성 시각·학습 시간(초)·크기(MB)
USER_MINING_MODEL_ATTRIBUTES
모델 시그니처의 속성명·논리/DB 타입·타깃 여부. TARGET=YES는 정답 컬럼이며 이 목록이 트리 분기 조건 전체를 뜻하지 않습니다.
USER_MINING_MODEL_SETTINGS
모델 설정과 INPUT(명시값) / DEFAULT(기본값). PREP_AUTO와 SQL의 수동 정제를 구분하세요.
USER_MINING_MODEL_VIEWS
Oracle이 생성한 실제 상세 뷰 목록. 트리 계층·노드·통계·타깃·비용 행렬 등의 제공 여부를 확인하고 실제 이름으로 조회합니다.
USER_MINING_MODEL_XFORMS
사용자 지정 내장 변환. PREPARED에 저장하는 INSERT SELECT의 CASE·TO_NUMBER는 여기 기록되지 않으므로 0행도 정상입니다.
USER_OBJECTS
MINING MODEL 객체 ID·VALID·DDL 시각. 웹 확정 상태를 저장하는 뷰가 아닙니다.

모델이 없으면 등록 정보가 0행입니다. 모델이 있어도 변환·상세 뷰 제공 여부에 따라 0행일 수 있습니다. 조회 오류는 0행으로 바꾸지 않고 오류로 안내합니다. 상세 뷰 이름·열 구성은 알고리즘과 DB 버전에 따라 다릅니다.
